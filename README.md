# STATE OF PLAY — UI & Motion Library

**v4.10.3 / 25カテゴリ・603パーツ**。触って選び、ソースと意図を自分の開発へ持ち出すUIパーツ集です。
表現と素材感を重視するAタイプと、落ち着いた実用的なBタイプを収録しています。

> ベースとなるv4.0.0は、未保存だった追加分をv3.8.0から再実装した版です。以前の未保存ソースと同一ではありません。
> 既存280パーツの本体は維持しています。経緯と照合は [RECOVERY.md](docs/RECOVERY.md) を参照してください。

## v4.10.3の修正 — タブのスクロールバー

Aurora TabsでNotesを選ぶだけで横スクロールバーが出る問題を修正しました。24種類すべてで、項目が実際に幅を超える場合だけ横スクロールを有効にし、つまみとレールは各パーツの素材色・形に合わせています。詳細のコード・使い方・AI用プロンプトも更新しました。[原因と検証](docs/TAB-SCROLL-FIX.md)を参照してください。

## v4.10.2の修正 — プルダウンの閉じ際

Kinetic系12種類で、閉じた候補一覧を退出演出用に再表示していたため、一瞬だけ全項目が見える問題を修正しました。閉じた瞬間に候補面を非表示にし、短い反応はトリガーに残します。全36種類の実クリック・閉じた次のフレーム・Escapeを確認し、使い方・AI用プロンプト・配布ソースも同期しました。[原因と検証](docs/DROPDOWN-CLOSE-FIX.md)を参照してください。

## v4.10.1の統合 — WAYFINDER

パンくずAタイプ10種類と数値入力Aタイプ13種類を改修しました。パンくずは階層線・紙の重なり・現在地の文字組み、数値入力は操作キー・ダイヤル・水位計など、配置と動きから作り分けています。直接入力、長い階層名、省略項目のリンクを維持し、詳細コード・使い方・AI用プロンプト・配布ZIPも更新しました。同名素材を両カテゴリで併用しても色が混ざらないCSS境界と、設定更新時に省略メニューを閉じる動作も補いました。ローカルで削除済みのPaper Loaderは戻していないため、全603パーツ・ローダー39種類です。[差分の原記録](docs/PATCH-v4.10.0.md)と[このリポジトリの統合検証](docs/WAYFINDER-INTEGRATION-VERIFICATION.md)を区別してください。

## v4.9.2の修正 — 起動表示

## v4.8.0の改修 — CONTINUUM（履歴）

進捗表示16種、ファイル選択13種、日時選択13種の**Aタイプ42種**を改修しました。

## 開発

Node.js 22.12.0以上を使います。PowerShellでも同じコマンドです。

```sh
npm install
npx playwright install chromium
npm run dev
```

ターミナルに表示されるURLを開きます。ソースの `index.html` をダブルクリックする方式ではありません。
`npm run build` が配信用の `dist/` を作り、`npm run preview` でビルド結果を確認できます。
この配布環境ではnpm接続が制限されているため、ロックファイルは捏造せず同梱していません。
既存のロックファイルがあれば保持し、`npm install` で更新したものをGit管理してください。

## 検証と全体ZIP

```sh
npm run typecheck
npm test
npm run verify
npm run package
```

`verify` は全体の型チェック・単体テスト・実Viteビルド・各ブラウザー検証を実行します。
`package` はリポジトリ全体を `release/` に出力し、CRC・SHA-256を照合します。
今回のテスト範囲は [REFINEMENT-VERIFICATION.md](docs/REFINEMENT-VERIFICATION.md) を確認してください。v4.2の記録は [SCULPTURE-VERIFICATION.md](docs/SCULPTURE-VERIFICATION.md) にあります。v4.1の記録は [ATELIER-VERIFICATION.md](docs/ATELIER-VERIFICATION.md) にあります。従来版の記録は [FINAL-VERIFICATION.md](docs/FINAL-VERIFICATION.md) に残しています。
ネットワーク制約下のオフライン検証は実Vite・指定依存バージョンの検証と区別しています。

## パーツを持ち出す

カード内のパーツはその場で操作でき、余白や「CODE」から詳細を開きます。
コード、使い方、AI用プロンプト、ファイル一覧を整理して表示します。

- React TSX / JSX、通常サイト向けTS / JSの4形式。
- 「導入向け」はパーツ本体と必要な補助処理が1つのフォルダーで完結。「元の構成」は元の階層を保持。
- コピーに成功したときだけ、成功表示を出します。拒否された場合は手動コピーできます。
- 「ファイルを保存」は選択中のファイル。「パーツZIP」は依存・使用例・説明・プロンプトを階層ごと含みます。
- ZIPのテキスト保管用形式は閲覧用です。通常ソースの代わりに直接実行する形式ではありません。

プレビューに入力した値・ファイルは送信・永続保存しません。実際の検索、保存、通知の発行、アップロード、検証などは利用先へ接続してください。
A/Bは見た目・使いどころの方向性であり、対応する公開APIを無視した実装や安全性の保証ではありません。

## 構成

```text
src/app/           ギャラリー・詳細・コード・保存UI
src/catalog/       掲載定義・配布レイアウト・共通プロンプト
src/parts/         各パーツの正本（CSS、HTML、TSX、TS、説明）
src/shared/        共有コントローラー
scripts/           Viteカタログ、ソース変換、ZIP生成
tests/             単体・ブラウザー・移動配置の検証
public/            アイコン、コード表示／ZIP用ライブラリ
```

`packages/`を常時生成しません。配布形式を正本から生成し、コード表示とパーツZIPで同じ内容を使います。
長い共有ソースはカタログの転送時だけ重複をまとめ、表示／配布するときには元の本文を損失なく復元します。
`node_modules`、`.test-output`、`dist`、`release`、`.git`、秘密情報は全体ZIPへ含めません。

## 既存リポジトリの置き換え

まずバックアップし、未コミットの独自変更を退避してください。**`.git`は削除せず、既存の`package-lock.json`も保持**します。
ZIP内の `STATE-OF-PLAY/` の中身を既存リポジトリのルートへ配置してください。
ZIPのフォルダー自体をルートの中へもう一段入れないように注意してください。
v3.8.0からの移行では元パーツを削除せず、新規カテゴリと関連コードを追加しています。
異なる変更履歴がある場合は、無条件の全削除ではなく差分を確認して統合してください。
GitHubへのコミット・pushは、このZIPの取得や展開では行われません。
