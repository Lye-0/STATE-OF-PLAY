# STATE OF PLAY

素材感と動きを備えたUIパーツを、実際に操作して選べるライブラリです。現在のバージョンは **4.16.0**。ReactとVanillaの実装、使い方、AI用プロンプト、個別ZIPを提供します。

## DEPLOYMENT

https://lye-0.github.io/STATE-OF-PLAY/

## 展示と詳細

- カテゴリとA/Bフィルターでデザインを比較し、各パーツを直接操作できます。初期表示はトグル。「すべて」は24件ずつ表示します。
- カードの余白または「CODE」から詳細を開き、コード・使い方・プロンプトを確認できます。
- 詳細では実装形式と配置を選び、ファイルのコピー・保存やパーツZIPの取得ができます。プロンプトはコード込み／文章のみを選択できます。
- Liquid Glassは詳細の「透明度」と「背景のぼかし」で調整できます。面・持ち手・展開パネルの濃淡を保ち、プレビュー、配布コード、プロンプト、ZIPへ反映します。展示のテンプレートは変更しません。

## 開発を始める

Node.js **22.12.0以上**とnpmを使用します。

```sh
npm ci
npm run dev
```

ターミナルに表示されたURLを開いてください。

```sh
npm run build
npm run preview
```

`dist/` に本番用の静的サイトを生成します。相対パスで配信できる構成です。

## GitHub Pagesで公開する

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
2. **Actions → Deploy GitHub Pages → Run workflow** から **main** を選び、実行します。
3. 完了後、デプロイジョブに表示されるURLを開きます。通常の公開先は `https://lye-0.github.io/STATE-OF-PLAY/` です。

[公開ワークフロー](.github/workflows/pages.yml) は手動実行式です。型チェック・本番ビルド・静的配信のブラウザー検証が成功した場合に、`dist/` を公開します。Pages設定から配信パスを取得するため、プロジェクト用のサブパスと独自ドメインの両方に対応します。初回のPages有効化は上記の設定画面で行ってください。

公開用と同じサブパスでローカル確認する場合は、次を実行します。

```sh
npm run build -- --base /STATE-OF-PLAY/
npm run test:pages
```

ブラウザー検証には、検証手順にあるChromiumのインストールが必要です。リポジトリ名や独自ドメインを変更した場合、`test:pages` の `PAGES_BASE_PATH` 環境変数を配信パスに合わせます（独自ドメイン直下は空文字）。この検証はSPAのフォールバックを使わず、37カテゴリ、詳細への直接リンクと再読み込み、コードとプロンプト、ファイルとZIP保存を確認します。

## パーツを持ち出す

| 形式 | 内容 |
| --- | --- |
| TSX | React + TypeScript |
| JSX | React + JavaScript |
| TS | HTML + TypeScript |
| JS | HTML + JavaScript（ES Modules） |

配置は、必要な依存を本体フォルダー内へまとめる **導入向け（portable）** と、`src/parts/`・`src/shared/` の階層を保つ **元の構成（original）** を選べます。React版は利用先のReact環境が必要です。Vanilla版に実行時の外部ライブラリ依存はありません。

既存アプリへの組み込みは [導入ガイド](docs/INTEGRATION.md) を参照してください。個別のAPIは各パーツの詳細画面と `src/parts/<category>/<id>/usage.md` に記載しています。

CLIでパーツZIPを生成することもできます。

```sh
npm run export:parts -- --part chrome --format tsx --layout portable
```

`release/parts/` に出力します。`--part` を省略すると全パーツ、`--format` を省略すると4形式、`--layout all` で両配置を生成します。

リポジトリ全体のソースZIPは次のコマンドで生成します。

```sh
npm run package
```

`release/STATE-OF-PLAY-v4.16.0-full-repository.zip` にソース・設定・テスト・文書と `RELEASE-MANIFEST.json` を収録し、CRCとSHA-256を検証します。`node_modules/`・`dist/`・検証生成物は含みません。

## 検証

```sh
npm run typecheck
npm test
npx playwright install chromium
npm run verify
```

`verify` は型チェック、単体テスト、本番ビルド、ブラウザー操作、配布後の独立動作までを順番に確認します。Linuxでブラウザーのシステム依存も必要な場合は `npx playwright install --with-deps chromium` を使います。

GitHub ActionsはUbuntu / Windowsの各環境で、preflight・gallery・relocation・controls・features・glassの6グループに分けて検証します。個別のテストコマンドは [package.json](package.json) を参照してください。
