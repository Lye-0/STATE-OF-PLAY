# STATE OF PLAY — UI & Motion Library

触って選び、ソースと意図を自分の開発へ持ち出す、UIパーツのコレクションです。
トグル・ブロック／カード・スクロールバー・プルダウン・アコーディオン・テキストボックス・ボタン・タブ・セグメント・チェックボックス・ポップアップを各24種類、リンク16種類、合計280パーツ収録しています。
素材感・動きを主役にする **A（表現重視）** と、落ち着き・実用性を重視する **B（実用重視）** をカテゴリと組み合わせて探せます。

**以前のv3.3.0では、スクロールバーのコレクションを24種類追加しました（A16種類・B8種類）。**
スクロール領域はネイティブのoverflowを使い、ホイール・タッチ操作を横取りしません。比例サイズのつまみ、ドラッグ、レールのクリック、キーボード、縦／横方向、内容変更、複数配置に対応します。詳細では方向、先頭／中央／末尾、短い内容での挙動を試せます。

既存48パーツとLiquid・Fold・PrismのON/OFF改善も維持しています。
既存のBトグル6種はCSS＋軽量なイベント処理、Bブロック8種はCSS主体の汎用コンテナです。
「導入向けの独立フォルダー／元の構成」の選択は引き続き使えます。
配置・コード・使用例・プロンプト・ZIPを同じ生成モデルから作り、移動に合わせて読み込み先も更新します。
v3.0.0で導入したVite＋TypeScriptの開発構成と、既存の素材感・構造・操作を引き継いでいます。
ギャラリー自体はReactへ全面移行していません。持ち出すパーツのReact TSX／JSX対応は継続しています。

一覧と追加内容は [280パーツのカタログ](docs/COLLECTION.md) を参照してください。

## 起動

Node.js 22.12.0以上を用意し、リポジトリのルートで実行します。

```powershell
npm install
npm run dev
```

ターミナルに表示されるURL（通常 `http://localhost:5173`）を開いてください。
`index.html`のダブルクリックではなく、Viteの開発サーバーで表示します。

初回の`npm install`で`package-lock.json`が生成されます。生成したロックファイルはGit管理してください。
ロックファイルがある環境では、再現用のインストールに`npm ci`を使えます。
今回の配布環境ではnpmレジストリへの名前解決ができず、ロックファイルを実生成できませんでした。
不完全なロックファイルを手作業で同梱することは避けています。直接依存のバージョンは`package.json`で固定しています。

## 以前の全体ZIPからの入れ替え

**最初に、既存フォルダーを丸ごとバックアップしてください。`.git`は削除しません。**

1. 未コミットの修正・独自設定・環境ファイルを退避します。
2. ZIP内の`STATE-OF-PLAY/`の中身を、リポジトリルートへ配置します。
3. 旧版の不要ファイルが残らないように入れ替えます。単純な上書きだけではファイル数は減りません。
4. `npm install`、`npm run dev`を実行します。
5. 差分を確認し、`package-lock.json`とともにコミットします。

削除対象と残すべきものは [移行手順](docs/MIGRATION.md) に記載しています。
このZIPに`.git`、`node_modules`、`dist`、秘密情報、単一HTMLプレビューは含みません。
GitHubへの自動コミット・pushは行いません。

## このサイトでできること

- ギャラリーでカテゴリ・A/Bの方向性・検索を使い、パーツを実際に操作する。
- トグルの余白やCODEボタンから詳細を開く。トグル自体のクリック／ドラッグはデモ操作。
- 整理された詳細画面で、動作、コード、使い方、AI用プロンプトを確認する。
- TSX／JSX／TS／JSの形式を選ぶ。行番号・構文色分け・折り返し・フォルダーツリーを使う。
- 選択中のコードをコピー／1ファイルで保存する。コピー成功／手動コピーのUIを使う。
- パーツZIPを「導入向け（推奨）」または「元の構成」で取得する。本体・専用補助処理・参考例を区別する。
- 配置規約を確認してから組み込むAI用プロンプトと、入口・用途・配置対応を記録した`INTEGRATION.json`を取得する。
- 必要に応じ、テキスト保管用ZIPを選ぶ。通常のソースZIPとは用途が異なります。

API・ログイン・データベース・ブラウザー上の追加画面はありません。パーツはソースで管理します。

## 管理するもの・生成するもの

```text
STATE-OF-PLAY/
├─ src/
│  ├─ app/               # ギャラリー・詳細画面・コピー・ZIP UI（TypeScript）
│  ├─ catalog/           # 型・カテゴリ・掲載定義・UI/ZIP/CLI共通の配布モデル
│  ├─ parts/             # 184パーツの元実装・仕様・React/Vanilla例
│  ├─ shared/            # 共有の描画・ばね・入力・アーカイブ処理
│  └─ main.ts            # Viteの入口
├─ scripts/
│  ├─ catalog.ts         # メモリ上で配布ソースを構築
│  ├─ vite-catalog.ts    # カタログ・マウント・CSSのVite仮想モジュール
│  ├─ layout.ts          # 元パスと配布パスの対応
│  ├─ source-tools.ts    # 構文に基づく参照解決・形式変換・独立デモ生成
│  ├─ templates/         # 全パーツで共有する独立デモの枠と初期化
│  ├─ export-parts.ts    # 任意の一括パーツZIP出力
│  └─ package.ts         # リポジトリ全体ZIP
├─ public/vendor/       # Prism / JSZip（同じファイルを重複配置しない）
├─ tests/
├─ docs/
├─ index.html
├─ vite.config.ts
└─ package.json
```

普段の開発・ビルドは`packages/`を作りません。
`virtual:sop-catalog`に、配布形式別のコード文字列・パス・ガイドを生成します。
実行用モジュールは元のTypeScriptからViteが処理し、コード欄は元ソースから作った読みやすいコードを表示します。
**圧縮済みのサイトJavaScriptをコピー用のソースとして見せる方式ではありません。**

開発用ソースは元の構造で1か所ずつ管理します。配布時に「導入向け」と「元の構成」のパスを作り、必要な共通処理を含めます。
本体が使用例に依存したり、パーツフォルダーの外へ参照が漏れたりする構成は、生成時にエラーにします。
JSとJSXはTS／TSXから生成します。ブラウザーへTypeScriptコンパイラーを配信しません。
独立デモは共通テンプレートから組み立て、個別パーツのHTML・CSS・JSとしてZIPへ保存します。

生成されるのは次の場所だけです。

| 場所 | 用途 | Git・全体ZIP |
| --- | --- | --- |
| `dist/` | サイトの本番ビルド | 対象外 |
| `release/parts/` | 任意で生成するパーツZIP。標準192種類、両配置で384種類 | 対象外 |
| `release/` | リポジトリ全体ZIP | 対象外 |
| `.test-output/` | テスト中の配布ファイル・結果・画面 | 対象外 |
| `node_modules/` | 開発用依存 | 対象外 |

`node_modules`を含めたPC内の総ファイル数を小さくすることが目的ではありません。
元実装と展開済み配布コピーを分離し、管理・交換するリポジトリを小さくしています。

## パーツを持ち出す

詳しい手順と構成の例は [導入ガイド](docs/INTEGRATION.md) を参照してください。
**全体ZIPは開発用リポジトリの置換、パーツZIPは既存アプリへの組み込み**に使います。
配置の選択はパーツZIPだけに適用されます。全体ZIPは常にリポジトリの階層を保持します。

サイトを使わず、同じ配布処理をCLIから呼ぶこともできます。

```powershell
# 指定したパーツ・形式だけを、2つの配置で生成
npm run export:parts -- --part chrome --format tsx --layout all

# 全パーツ・全形式を元の構成で出力
npm run export:parts -- --layout original

# 導入向けのテキスト保管用ZIP
npm run export:parts -- --part chrome --format js --mode text
```

書き出すのは`release/parts/`のみです。生成ファイルを`src/`や`packages/`へ展開しません。
このCLIはインストーラーではなく、導入先を読んだり上書きしたりする処理はありません。

## WindowsのZIP警告

ZIPは通常のDEFLATE形式です。ディレクトリ・同名ファイルの別階層を保持し、不正なパスを拒否します。
ダウンロードしたファイルへのWindowsの入手元情報やDefender/SmartScreenの判定は、ZIPの整合性とは別です。
警告を必ずなくす保証や、保護機能を無効化する操作は含みません。
テキスト保管用は拡張子に`.txt`を加えるだけで、そのまま実行する形式ではありません。
