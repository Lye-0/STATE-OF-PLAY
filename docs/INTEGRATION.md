# 既存プロジェクトへの導入

## 形式と配置を選ぶ

パーツの詳細でTSX / JSX / TS / JSと配置を選び、ZIPを取得します。画面のコード・使い方・プロンプトとZIPは同じ配布データを使用します。

| 配置 | 取り込む内容 |
| --- | --- |
| 導入向け（portable） | パーツの本体フォルダー。必要な共通処理は内部にまとまる |
| 元の構成（original） | 必要な `src/parts/`・`src/shared/` の階層ごと |

本体フォルダーを任意の場所へ配置し、外側からのimportを配置先に合わせます。内部の相対参照を保つため、CSSや `internal/` も一緒に取り込んでください。ZIPの `examples/` は使用例、`preview/` は独立確認用で、既存アプリの入口へ上書きするファイルではありません。

ZIP内の `README.md` は選択した形式・配置の導入手順、`PROMPT.md` はAI用の仕様、`INTEGRATION.json` は入口・依存・元パスと配布パスの対応です。実際のファイル一覧はパーツにより異なります。

## アプリへ接続する

React版はReact 18以上の環境を用意し、公開コンポーネントをimportします。TSX / JSX、CSS import、クライアント処理の扱いは利用先のビルド・SSR構成に合わせます。Vanilla TS版はTypeScriptを変換し、JS版はHTTP配信のES Modulesとして使用します。

Vanillaでは配布されたマークアップの部品ルートを `init` へ渡し、取り外す際に返り値の `destroy()` を呼びます。React版はコンポーネントのライフサイクル内で後片付けします。オプション・制御値・イベント・内容スロットは、各パーツの詳細と `usage.md`、型定義、使用例を参照してください。

展示のサンプルデータを、利用先の値・候補・リンク・非同期検索・実行処理などへ接続します。同じパーツを複数配置した場合も、状態とIDが独立することを確認してください。画面の読み込み表示や展示背景は、配布パーツの必須依存ではありません。

## Liquid Glassの調整

詳細の「素材を調整」で、透明度と背景のぼかしを独立して設定できます。どちらも **50が展示の設定** です。

| 項目 | 0 | 50 | 100 |
| --- | --- | --- | --- |
| 透明度 | 各面を濃くする | 展示の濃淡 | 各面を薄くする |
| 背景のぼかし | ぼかしなし | 各面の基準 | 各面の基準の2倍 |

透明度は部品全体のopacityではなく、背景色のアルファを調整します。文字・輪郭・影を保ち、本体・持ち手・選択面・展開パネルの濃淡も連動します。背景をくっきり見せるには透明度を上げ、ぼかしを下げます。展示カードの設定は変更しません。

変更はプレビュー、4形式・両配置の配布コード、両プロンプト、ZIPと独立デモへ反映します。値はZIPの `INTEGRATION.json` の `glassTransparency` / `glassBlur` に記録します。配布CSSでは `--lg-alpha-scale` / `--lg-alpha-lift` / `--lg-blur-scale` を使い、展示基準の `--lg-density` / `--lg-control-density` を保持します。

`lgc-root` を持つスキンは `data-lg-appearance="light"` / `"dark"`、`data-lg-material="solid"` と素材用CSS変数でも調整できます。先行の `lg-` パーツを含め、利用可能な属性・APIは個別の `usage.md` を確認してください。背景を自動解析する共通APIではありません。透明度低減・強制配色・solid表示は素材調整より優先されます。

## 更新と確認

既存の同名ファイルや共有処理を無条件に上書きせず、ID・バージョン・元パスを比較します。portableの異なる部品に同名の内部ファイルがあっても、名前だけで共通化しないでください。

導入後はマウス・タッチ・キーボード、ラベル・フォーカス、フォーム、無効状態、狭い画面、縮小モーション、背景に対するコントラストを確認します。詳細のAPIを変えた場合は、利用先のイベント・値との接続も確認してください。
