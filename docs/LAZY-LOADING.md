# カテゴリ別読み込みと外部差分の統合

## 現在のブラウザー構成

初回は一覧用メタデータとトグルカテゴリを読み込みます。カテゴリ選択時に、そのカテゴリのマークアップ・CSS・initを動的importします。詳細を開いた時だけ、そのパーツの配布データ（4形式×2配置、説明、プロンプト、独立デモ）を取得します。

- `scripts/vite-catalog.ts`: registryから軽量インデックス、カテゴリモジュール、パーツ別JSONを生成。開発時は要求されたパーツだけ生成し、本番はハッシュ付きJSONアセットを出力します。
- `src/catalog/browser.ts`: カテゴリと詳細のPromiseキャッシュ。配布JSONの失敗はキャッシュから外して再試行します。カテゴリモジュールの失敗はブラウザーにもキャッシュされるため、カテゴリ・検索・A/B条件をURLへ引き継いでページを再読み込みします。
- `src/app/gallery.ts`: 初期カテゴリ、非同期描画、古い応答の破棄、検索、Allの追加表示。
- `src/app/details.ts`: 非同期詳細と閉じる操作による読み込み結果の無効化。別カテゴリの関連パーツと履歴移動にも対応します。
- `scripts/catalog.ts`: 正本からの配布生成。従来の全件生成APIを残し、任意のIDリストによる限定生成を追加しています。

カテゴリタブの縦方向のはみ出しは隠し、横方向の移動だけを許可します。カテゴリ取得中は前のカード一覧の高さを保持して、ページのスクロール位置が跳ねないようにします。矢印キーでのフォーカス移動もページを動かさず、必要な横方向だけをスクロールします。

「すべて」は24件ずつ追加表示します。追加時には既存のカードを再初期化しません。名前・素材・タグ・A/B検索は全件の一覧情報を使い、選択カテゴリとの積で絞り込みます。初期の詳細URLはその部品のカテゴリを開きます。

カテゴリを離れるとコントローラーとデモの後片付けを実行します。取得したJS/CSSはブラウザー内に残り、再選択で再利用します。CSSを毎回除去する方式ではないため、カテゴリの初回・混在・異なる読み込み順の検証が必要です。共通処理・共通CSSは必要なカテゴリ間で共有されます。トグルの展示枠にはOriginal SurfaceのCSSも必要です。

一覧だけを見る段階で配布用テキストを取得しないことを保証対象とします。ビルドが全パーツの配布物を生成することとは別です。

## ChatGPT側から受け取る改修・追加差分

ChatGPT側は、このカテゴリ別読み込みへの変更を知らない状態でパーツの改修を進めています。旧サイト構造を含む差分・全体ZIPを、そのままリポジトリへ上書きしないでください。

1. 別の場所へ展開し、差分元の版と現在のGit差分を確認します。削除・上書きの前に既存の変更を確認します。
2. `src/parts/`のパーツ本体・meta・usage・promptと、必要な共有処理を一組で統合します。新規パーツは既存のregistryへ追記し、現在の登録を消さないようにします。
3. `src/app/`、`src/catalog/`、`scripts/`、`src/main.ts`、`src/env.d.ts`、設定・テストは変更内容を比較して統合します。全件の静的import、全配布ソースの初回読み込み、同期前提の詳細画面へ戻さないことを確認します。
4. デモやカテゴリ専用操作が追加されていれば、現在のプレビュー処理へ取り込みます。登録しただけで新しいカテゴリの操作UIまで自動作成されるわけではありません。
5. サイトのコード表示・コピー・説明・プロンプト・ZIPを、取り込んだ正本と照合します。共有処理の変更は、他カテゴリと独立配布先への影響も確認します。
6. 型チェック、関連する部品テスト、本番ビルド、`npm run test:lazy-loading`を実行します。未選択カテゴリや未表示パーツの配布JSONが初回に取得されていないことも確認します。

部品のID、フォルダー構成、meta.json、registry.json、公開API、各パーツのプロンプト形式は、この構造変更では変更していません。全件の正本カタログと配布生成APIも引き続きCLI・既存テストで利用できます。

## 検証

`tests/lazy-loading.browser.ts`は実Viteの開発・本番HTTPを使い、初期通信、カテゴリキャッシュ、Allの段階表示、検索、詳細の8形式/配置、プロンプト、直接リンク、履歴、読み込みキャンセル、エラー再試行、全25カテゴリのCSS読み込み順を確認します。

`tests/offline-fixture.ts`は制約環境専用です。互換性のため全データをメモリーへ収録しますが、通信量や本番のコード分割の証拠には使いません。
