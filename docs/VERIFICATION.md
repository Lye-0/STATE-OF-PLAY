v2.2.0で配布したサイトと16パーツを元に、全体置き換え用の開発リポジトリを組み立てたものです。
配布済みのパーツコードからTypeScript／TSXの正本を配置し、ギャラリーのJavaScriptも編集できるモジュールへ分割しました。
生成処理と回帰テストはこの構成で再実行しています。

## 環境・制約

Linux、Node.js 22.16.0、TypeScript 5.8.3、Chromiumを使用しました。
ブラウザー環境がlocalhostへのナビゲーションを管理ポリシーで拒否したため、
ポリシーは変更せず、生成した実ファイルをテスト用の空のドキュメントへ読み込んで確認しています。
これは通常HTTPナビゲーションを通したブラウザーテストではありません。
サイトとして配布するファイルは分離したままであり、単一HTMLを作成したという意味ではありません。

通常の環境では `npm run test:browser` が付属HTTPサーバー経由で検証します。
テスト環境固有の `SOP_OFFLINE=1` は一般の開発環境では不要です。

コピー成功シナリオでは許可済みClipboardをテスト用に再現し、書き込み対象の文字列を検証しました。
OSのクリップボードに書いたことや、ユーザー自身の保存先を確認したことは意味しません。
ダウンロードはブラウザーのdownloadイベントを受け取り、保存された内容を検査しています。

今回の再構成ではReactランタイムによる再実行とReact型定義を含む静的型チェックは実行していません。
ReactパーツのTSXは配布済みの実装を正本として保持し、JSXは同じ正本から生成しています。
`npm run typecheck:react` は依存関係をインストールした通常環境で実行できます。

Windows Explorer、Defender / SmartScreen、iOS / Safari実機、GitHub本番配信は今回検証していません。
Windowsの警告が必ず消えると保証するものではありません。

## 全体ZIP

通常のDEFLATE圧縮、DOS互換のZIPを生成します。
生成後にJSZipでCRC・SHA-256を照合し、さらにPythonのzipfileで展開して全ファイルを照合します。
`RELEASE-MANIFEST.json` はファイル一覧とSHA-256を記録します。

`.git`、`node_modules`、秘密情報、一時ビルド出力は除外します。
復元時の動作確認では、新しく展開したフォルダーからビルド・型チェック・単体テストを再実行します。
転送・格納の整合性と、セキュリティ判定は別のものです。
