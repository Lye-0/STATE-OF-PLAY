## 検証環境と制約

- Linux / Node.js 22.16.0 / TypeScript 5.8.3 / インストール済みのChromiumを使用しました。
- npmレジストリへのDNS解決ができず、新しい依存パッケージをインストールできませんでした。`playwright: "1.63.0"` の指定は公式npmの掲載と照合しましたが、この環境で1.63.0による動作確認、`npm install`、オンラインの `npm audit` を完了したという意味ではありません。
- ブラウザーテストは環境に既存のPlaywrightドライバー `1.57.0-beta-1764944708000` を検証時だけ使いました。このドライバーをソースZIPへ同梱していません。ユーザー環境ではpackage.jsonで指定した1.63.0を使用します。
- agent-browser CLIは未インストールでした。localhostへのブラウザーナビゲーションも管理ポリシーで拒否されたため、ポリシーを変更せず、Playwrightの `setContent` / `addStyleTag` / `addScriptTag` に実ファイルを読み込む既存のオフライン試験で確認しました。単一HTMLを配布することやネットワーク制限を解除することは行っていません。
- 通常のブラウザーからHTTP経由で取得する動作と、通常JS版のHTTP上のネイティブES Modulesはこの環境では未確認です。全相対パスの静的解決と、分離デモの読み込み・操作は確認しています。Node.jsからのHTTPサーバー応答は確認しています。
- React版は元のTSXを保持して変換・依存パス確認をしています。今回はReactランタイムでの再実行と公式React型定義による全TSXの型チェックを行っていません。
- コピー成功はテスト用のClipboard書き込み関数を用いて対象文字列を照合しています。保存はブラウザーのdownloadイベントで生成ファイルを受け取って検査しています。
- Windows Explorerによる展開、Defender/SmartScreen、iOS/Safari実機、GitHubの本番配信は実機確認していません。

## 通常の開発環境で再確認

```powershell
npm install
npm audit
npx playwright install chromium
npm run verify
npm run typecheck:react
```

通常の `npm run test:browser` はHTTPサーバー経由で試験します。正常な環境では `SOP_OFFLINE` や `PLAYWRIGHT_PATH` などの検証用変数は不要です。
`package-lock.json` は上のnpm installで更新/作成し、Gitで管理してください。この配布環境で取得できなかったレジストリのintegrity情報を作り物で補うことはしていません。

## 全体ZIPの独立照合

生成スクリプトは書き出し直後のZIPをJSZipで再読込し、CRCと全ファイルのSHA-256、全ディレクトリエントリーを検証します。
納品時はさらにPython zipfileで別フォルダーへ展開し、全ファイルとディレクトリを照合し、そこから再ビルド・コア型チェック・31件のテストを再実行します。
SHA-256/CRCは整合性の検証であり、セキュリティソフトによる無警告やマルウェア不在を保証するものではありません。
