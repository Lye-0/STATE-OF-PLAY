# UIの開発方針

提供された開発記録「STATE OF PLAY」「拡張」の要望本文・画像と、現行の実装・文書を照合した要約です。原本・画像・チャットの全文はリポジトリ外で保管します。参照チャットの直接取得はこのクラウド環境では利用できず、この文書は提供された記録を根拠とします。

## デザインの判断

- Aは実用性を維持しながら、形・素材・構造・操作時の動きで大胆な独自性を出す。トグルとブロックが方向性の参考。強い色、大きなマーク、太い枠だけで派手にしない。
- Bは落ち着いた美しさ、読みやすさ、組み込みやすさを優先する。Aを単に薄くしたものに限定しない。
- 色・角丸だけを変えた量産や、同じ意匠の別カテゴリへの意図的な横展開を避ける。共通の状態管理は再利用できるが、見た目は各操作に合わせて設計する。
- 暗緑の大きな面・同系色の枠・淡い黄緑の操作部を既定の配色として反復しない。紙・金属・石などの素材と情報階層に合わせて明暗を分ける。地形・植物・回路などの主題に合い、十分な個性がある緑は残してよい。
- 全カテゴリで合計30種類以上、A・Bそれぞれ5種類以上を維持する。A:B=3:1は目安で、比率のために似た部品を増やさない。
- 比較は静止画だけでなく、展開・選択・入力・ホバー時の状態まで含める。重複の判断をソースの共通率や画像スコアだけで決めない。

## 動作とレイアウト

- ホバー開始、解除、復帰途中の再進入が連続すること。模様・光・ローダーが瞬間移動したり、閉じたパネルが一瞬再表示されたりしないこと。
- 値・文字・キャレット・クリック対象は安定させ、背後の素材や装飾を動かす。値の確定をアニメーションの完了まで遅らせない。
- 不意の縦横スクロールバー、文字のはみ出し、ラベルの位置ずれ、操作時の幅の変化を避ける。必要なスクロールは部品の意匠と揃える。
- メニュー・ポップオーバーの開閉、スクロール追従、フォーカス復帰を確認する。キーボード・タッチ・長い日本語・狭幅・縮小モーションも実操作で検証する。
- 本体だけでなく、展開する選択肢・通知・ダイアログにもデザインを適用する。デフォルトUIを不用意に併設しない。

## Liquid Glassと詳細カスタマイズ

- 実際に背景を透かす素材感と、読みやすさを両立する。単なる白い半透明の箱や既存デザインのコピーにしない。
- 通常カテゴリの一員として展示し、ガラスだけ行高・本体幅・ラベル位置を特別扱いしない。透過が分かる背景と専用の詳細設定は使用できる。
- 透明度と背景ぼかしは別に調整する。変更後も面・持ち手・展開パネルなどの濃淡の関係を維持し、一律の不透明度へ潰さない。
- 展示は代表値。配色・透明度などの変更は詳細だけに適用し、展示や元カタログへ漏らさない。
- 配色は主要な1〜2項目に絞る。素材やON/OFFの意味に直結する色は保持する。色見本、自由な色選択、HEX入力を分かりやすく提供する。

## 配布とサイトの契約

- 修正はTS/TSXの正本に行い、React TSX/JSX・Vanilla TS/JS、portable/original、表示コード、コピー、使い方、プロンプト、ZIP、独立デモへ同じ結果を届ける。
- ギャラリーだけで動く見せかけの修正にしない。独立した利用先、React StrictMode、複数配置、解除後のイベント・RAFも確認する。
- カテゴリごとの遅延読み込み、詳細を開くときのソース取得、「すべて」の24件単位表示を維持する。旧パッチの全件importへ戻さない。
- サイト内でも配布パーツを利用する。現在のカテゴリ選択はAurora Select、配色設定はChromatic Orbit、ローダーはNixie LoaderとOrbital Loom。サイト用の依存と選択カテゴリ用の依存は検証でも区別する。
- パーツ利用条件の正本は `PARTS-LICENSE`。完成したアプリでの使用と素材としての再配布を区別し、第三者コードの通知は別に保持する。

## CI修正時の注意

過去の失敗には、固定件数、削除済み部品、古い選択肢、非表示のネイティブselect、表示準備前の操作、大量同時描画、OS間のタイミング差が含まれます。登録情報と実際に表示される操作対象を基準に検証し、失敗を隠すためのアサーション削除や機械的な再試行は行いません。表示上の不具合なら本体を直し、仕様変更で古くなった期待値なら、その根拠を確認してテストを更新します。

コミットメッセージは日本語のConventional Commits形式を用います。今回の依頼では修正・検証後にpushし、その後のActionsは追跡しません。
