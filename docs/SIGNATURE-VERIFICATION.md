## 対象と復元経緯

保存されていたv4.9.0全体ZIPに、実在するv4.10.0差分を適用した604パーツを基点にしました。直前の未完了作業の6カテゴリのソースは残っていなかったため、今回96種類を新しく実装しています。以前の未保存実装の完全復元という意味ではありません。

新規は6カテゴリ・各16種（A10 / B6）、計96種類。全体は31カテゴリ・700種類です。既存604パーツの本体6,040ファイルは基点とバイト単位で一致しています。

## 環境と確認していない範囲

- 実行環境はLinux、Node.js 22.16.0、TypeScript 5.8.3、インストール済みPlaywrightドライバーと `/usr/bin/chromium` です。
- agent-browserコマンドは存在せず、実際に試したローカルHTTPナビゲーションも管理側のブラウザーポリシーによりERR_BLOCKED_BY_ADMINISTRATORでした。制限を変更せず、Playwrightで同一の著者ソースを変換・ページへ読み込む明示的なオフライン方式を使用しました。
- npmレジストリへ接続できないため、実Viteのビルド/HMR/HTTP配信、`npm audit`、指定依存一式のインストールを実施していません。
- ReactのTSX/JSXは元ファイルの構文変換と配布依存を検査していますが、新作を実Reactのランタイムで動作させたという意味ではありません。公式React/Node/Vite型定義を含む `npm run typecheck` 全体、SSRの実hydration、StrictMode実行は未確認です。
- コピーはテスト用clipboardハーネスへの文字列と成功UIを検査しました。ユーザーのOSクリップボードへ書き込んだわけではありません。ZIPも保存Blobを読み取った検証です。
- Windows Explorer、Safari/iOS実機、各OSのIME、スクリーンリーダー、GitHub Actions/本番配信では未検証です。
- 見た目の評価と動作テストは別です。Aは形と操作固有の変化、Bは通常のフォーム/画面へ合わせやすい構成にしています。
- 全体の `npm run verify` 完走済みとはしていません。過去のログを今回の実行結果として扱っていません。

## ローカルで再実行

```sh
npm install
npx playwright install chromium
npm run verify
npm run dev
```

全体ZIPと差分ZIPの最終CRC・SHA-256照合、再展開したソースでの再テスト結果は同梱の `signature-checks/archive-validation.json` を参照してください。CRC/ハッシュは整合性確認であり、OSのセキュリティ警告が出ない保証ではありません。
