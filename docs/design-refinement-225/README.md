メインが約10件を実装して通常・操作・ホバー・狭幅を確認し、Astra / mediumの独立検査へ渡す。検査中は後続組の実装下書きと実画面検証を進める。指摘を反映し、必要なら再検査。検査を通った組だけをコミット・pushする。共有実装変更の波及対象は記録し検証する。

Aは色・角・枠だけの違いを避け、構造と操作の関係を個別に設計。Bは用途・情報階層・密度で使い分ける。文字・クリック領域・入力の安定、ネイティブ操作、狭幅、動き軽減、配布先の一致を維持する。

進捗は progress.json、対象は targets.json、設計・検査・対応・検証は batches/Bxxx/ に保存。画像と提出用単体HTMLはこのフォルダに集約しGit管理外。過去の添付原本・全文はコピーしない。Actionsはpush後に追跡しない。

## 提出と再確認

提出ファイルは `refinement-results.html`。画像を埋め込んだ単体HTMLで、10件ごとの表示・番号/名称の検索・画像拡大に対応する。作業画像や提出物を削除する場合は、このフォルダ内にまとまっている。

`tools/verify-scope.py` は225件の対象一致と独立承認時の作者ハッシュを検証する。`tools/report.py` は保存済みの検査画像からHTMLを生成し、`tools/check-report.mjs` は全ページの画像・検索・拡大・狭幅を確認する。画像・snapshotはGit管理外のため、生成には今回の作業ファイルが必要。

`implement-*` / `revise-*` / `strengthen-*` / `fix-*` などの実装スクリプトは、実行済みの変更記録。既に適用されているため再実行しない。検証の範囲と実行結果は `verification.md` を参照。
