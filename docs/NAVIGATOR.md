## 導入

詳細欄の「導入向け」を選ぶと、パーツのフォルダーと `internal/` が一組になります。本体フォルダーを、既存のコンポーネント配置へ丸ごと移動してください。`examples/` と `preview/` は本体の依存ではありません。TSX/JSXはReact環境へ、TS/JSは通常のDOMへ導入します。フォルダーを分解する場合はimport・CSSの参照も更新してください。

新パーツのCSSは `.sop-wb.sop-<id>` へ閉じています。共通処理は `src/shared/workbench/` にあり、取得したパーツZIPにも含まれます。個別にコピーした複数パーツで識別子が衝突しないよう、各モジュールの名前空間とインスタンス番号を併用します。ギャラリーの `NAVIGATOR` タグで今回の部品を検索できます。

## DOMとReactの担当

React版はルート要素と設定を管理し、内部の `data-wb-owned` 以下は専用コントローラーが管理します。そこへReactの子要素を混在させません。見た目だけのHTMLではなく、同じコントローラーを通常HTML版とReact版の両方から呼びます。更新時に入力欄を作り直さず、Effectのクリーンアップでリスナー、待機タイマー、Observer、非同期処理を破棄します。

Reactの `apiRef` または通常版の `init(root, options)` の返り値から、`update()`、`getState()`、`reset()`、`destroy()` を呼べます。開閉する部品には `open()` / `close()` もあります。通常DOM版で部品を取り外す前には必ず `destroy()` を呼んでください。

## 検索バー

単なる装飾付きinputではなく、問い合わせ・対象フィルター・結果一覧・検索中／エラー／一致なしを扱います。デフォルトのサンプルはローカル配列です。`onSubmit(query, filter)` は検索ボタンまたはEnterで受け取れます。結果への実際のページ移動には `href`、アプリ内操作には `onResult` を使います。

`query` / `filter` は外部制御、`defaultQuery` / `defaultFilter` は初期値です。外部制御では `onQueryChange` / `onFilterChange` で親の状態を更新してください。`items` によるローカル検索か、`search(query, filter, signal)` が返すPromiseによる非同期検索を利用できます。非同期検索の結果はサーバー側の絞り込みを正として再フィルターしません。後者は新しい検索で古い処理をabortし、順序が逆転して返っても古い結果を適用しません。`debounceMs` の既定は180msです。

IME変換中にEnterを確定処理として横取りせず、入力確定後に検索します。候補を選ぶ操作は上下キー／Enter、Escapeは候補を閉じます。フォームに入れる際は `name` を設定できます。サーバー、履歴保存、分析用の送信は含みません。

## コマンドパレット

`items` には `id`、`label`、任意の説明、グループ、アイコン名、ショートカット表示、`children` を指定します。`children` は次のコマンド一覧へ進む階層です。Backspace（検索欄が空のとき）または戻るボタンで1階層戻ります。

`onExecute(item, signal)` が実行先です。Promiseを返すと重複実行を止め、処理中表示をします。`false` を返すと閉じず、例外はパネルに表示します。閉じる／取り外す操作はシグナルをabortし、古い完了結果を無視します。

`hotkey: true` のインスタンスだけがページ全体のCtrl+K / Command+Kを使用します。アプリで原則1個だけ有効にしてください。既定はfalseです。部品内にフォーカスがある場合はローカルのCtrl+Kも使用できます。複数置いたギャラリーはグローバルのショートカットを登録しません。候補に表示するNやG Pなどはヒント文字列であり、そのキーを全ページで勝手に登録する実装ではありません。

native `dialog.showModal()` を使い、開いた後は検索欄へ、閉じた後は元の操作位置へフォーカスを戻します。外部制御 `open` では `onOpenChange` から親状態を更新します。

## コンテキストメニュー

対象は部品内の領域のみです。そこでの右クリック、Shift+F10、または明示した「…」ボタンで開けます。ページ全体の `contextmenu` は変更しません。タッチでは「…」から利用でき、長押しをグローバルに妨害しません。

既存の行・カード・任意の要素へ付けたい場合は、`targetElement` にそのHTMLElementを渡します。展示用の表面は隠れ、その要素だけへcontextmenuとShift+F10のイベントを登録します。要素の中身は作り直しません。対象はキーボードでも到達できるようにし、タッチ用のボタンからは返されたAPIの `open()` を呼んでください。`update({targetElement: next})`で古い対象のリスナーを解除して付け替えられ、nullで標準の表面へ戻ります。Reactでは対象要素をcallback ref等で取得して渡します。ページ全体への自動適用はしません。

`items` の `kind` はaction / checkbox / radio / separatorです。radioはgroup単位で単一選択します。子項目は同じパネル内のドリルダウンとして表示し、→で開く、←で戻る、Escapeで戻る／閉じるを操作できます。デスクトップの多段フライアウト方式ではありません。上下キー、Home/End、先頭文字も使用できます。

無効項目は説明を読むためにフォーカス可能ですが、実行しません。`checked` は外部制御、`onCheckedChange` で次のチェック状態を受け取ります。実際の操作は `onAction(item, signal)` で接続します。削除等を勝手に実装しません。ポップオーバーは画面内へ収まる位置を計算し、メニューのスクロールを妨げないようにしています。

## ナビゲーション

`layout` はheader / sidebar / dock / mobileです。各スキンのReactラッパーには、その見た目に合う既定配置があります。ラベル・URL・階層・アイコン・バッジは `items` から指定します。

通常項目は本物の `<a href>`、下位の一覧を開く部分はbutton/disclosureです。ナビゲーションへ不要な `role="menu"` は付けません。中クリック、Ctrl/Command付きクリック、右クリックを横取りしません。

`onNavigate(item, event)` が `false` を返すと通常クリックの標準遷移を止めるため、既存のルーターへ接続できます。それ以外はリンクとして遷移します。`active` / `onActiveChange` は外部制御、`defaultActive` は初期値です。現在地は `aria-current="page"` で示します。ギャラリーだけは遷移を止め、選択中の現在地をパーツ内で更新します。取得したパーツのhrefは利用先の実URLへ変更してください。

デスクトップの階層を展開して子リンクを選ぶと、非制御時は現在地の名前に加えて親の展開ボタンと選択面も反応します。外部制御では `onActiveChange` を受けて `active` を更新してください。固定位置に開く子一覧は、一覧内だけのスクロールでは維持し、ページや周囲のスクロールでは閉じます。子リンクへのポインター操作中にフォーカスが一時的に移っても、クリック前に一覧を閉じません。

画面が狭いとヘッダーはメニューボタンへ切り替わります。モバイルメニューはnative dialogで開閉し、Tab・Escape・フォーカス復帰を扱います。選択マーカーのサイズは実際のラベルを計測するため、4項目専用の固定幅ではありません。

## テーブル／データグリッド

今回の実装は、検索・ソート・選択・固定列・列幅変更・行操作・ページ送りを備えた**読み取り中心のネイティブHTMLテーブル**です。Excel型のセル編集、仮想スクロール、列並べ替え、複数列ソートは含みません。スプレッドシートのキーボード操作を約束するARIA gridへはしていません。

`columns` は `id`、`label`、kind（text / number / date / badge / progress）、width、sortable、align、formatから定義します。formatは文字列としてエスケープされます。任意HTMLの挿入は行いません。`rows` のidは安定した固有値にしてください。

ローカルモードは、渡された行を検索・ソート・ページ送りします。数値は数値として、同値は元順序を保ち、空値は末尾へ配置します。元の配列を直接変更しません。ソートは昇順→降順→解除です。選択は行idで管理し、並べ替えで別行へ入れ替わりません。ヘッダーの一括選択は「現在のページの選択可能な行」が対象です。

列境界はドラッグか、フォーカスして左右キー（Shiftで1px）・Home/Endで幅を変更できます。範囲は88〜520pxです。固定する先頭列・選択欄、横スクロールできる領域を分けています。最大行数はアプリの性能に合わせて決めてください。数万行をそのまま描画する用途ではサーバー側ページ送り／専用の仮想化実装を検討してください。

### サーバー側の検索・ページ送り

`manual: true` では、渡した `rows` を再検索・再ソート・再スライスしません。`rowCount` を総件数として設定し、`query`、`sort`、`page` を親から渡します。`onQueryChange`、`onSortChange`、`onPageChange` を受けてサーバーへ問い合わせ、その結果をrowsへ戻してください。

`selected` を渡すと選択は外部制御です。`onSelectionChange(ids)`、`onRowAction(action, row)` が接続先です。loading、error、0件表示も指定できます。行を削除する処理、通信、権限確認はアプリ側の責務です。

## 動きの方針

検索はフォーカス時の膜・レール・入力面、コマンドは展開と候補への焦点、メニューは扉や短冊の展開、ナビゲーションは経路・選択面、テーブルは列と行の状態を中心に表現します。入力位置や確定値を装飾のために遅らせません。常時のJS描画ループはありません。prefers-reduced-motionとforced-colorsの静止／識別可能な表示を用意しています。
