# B046 最終再設計

## file-jacket-context

実対象名を全幅の起点バーへ置き、84px（狭幅64px）の支持面を本文の左へ接合し、実分類ごとの読む紙を幅56pxの斜めの接合で分岐させる。分類数だけ実groupを作り、分類なしには見出しを作らず一枚の紙へ戻す。submenuの起点名は現在の実親へ切り替わる。下ポケットを廃し、実対象・分類・操作の情報の関係が仕分け面の形を決める。

## inspection-card-context

各行の白丸と丸い片端を廃止し、実状態glyphを一つの深い検査溝へ並べる。64pxの溝の片側に16pxの断面、反対側に20pxの開口を置き、実名称・説明・分類は連続した不透明な紙へ読む。checkedの実小面だけが溝を塞ぎ、普通のactionには偽のチェックを作らない。disabledも面を透過させず、native状態と文字色で区別する。

## folding-dossier-context

操作ごとの交互折片を全廃し、現在の実メニューだけを載せる一枚の前紙を、大きい非対称の64px折面へ16px入れる。実親へ戻る場合だけ、幅80pxのnative戻るを開いた横差し受けへ置く。祖先数で折面を増やさず、header・現在の実親・実操作の二領域の接合を読む。分類とdisabled本文は不透明な紙を保つ。

## stitched-file-context

上の輪と取っ手を廃止し、44pxの実起動を96pxの一つの接合軸へ置く。軸から非平行な二枚の幅広い支持片が開き、実対象の名称面と操作の読む面を保持する。展開メニューも一つの軸と二方向の支持を持ち、字とnativeボタンは動かさない。閉じた四辺枠・上部アーチ・縦の通し縫い背には戻さない。

## receipt-command

実queryの平らな送り面と、実候補件数を読む88pxの端面を一体の送り部材にする。候補紙は40pxの深い開口へ16px入り、20pxの前唇が紙の上32pxを覆う。native読字は開口の下へ48px離して守る。切断紙を丸い検索欄へ載せる構成から、実query・件数・差込みの断面が役割を持つ主形へ変える。

共有Contextのsubjectは既存表示では非表示。実分類に連続する実role=groupのwrapperを作り、匿名群には偽見出しを作らない。変更5件に採用し、既合格5件の正本は維持する。

最終読字修正：R631の長い実対象名は全幅のバーで折り返す。R633の実親名には不透明な紙面を接合し、Back受けの侵入から文字を保護する。
