# B040 原版5点への設計提案

対象は immutable round-0 のR553/554/555/557/558。元監査の理由と `captures/timelines-self-0/*-expanded.png`、実markupの `time / summary(title,status,chevron) / body(description,meta,href)` を確認した。以下は設計候補であり合格の先取りではない。名称の文字どおりの再現より、時系列の読みと開閉操作が大きい形を決めることを優先する。

共通条件：日時の任意文字列を切らず、本文14px以上、summaryの実押面44px以上。状態は既存の「完了／進行中／予定」を読める文字で示し、架空の目盛り・ID・数値を加えない。hoverで日時・見出し・状態・hitを動かさない。開閉で後続イベントが下がるのは自然だが、同じsummary内のglyphは動かさない。320pxでは日付を上段へ移して本文を全幅にする。RTLは材料だけを必要な一回だけ鏡映し、数字列・日付表記の方向は内容に合せる。

## R553 Folded Memory — 日付を載せた立体の折り耳と、自由な記録紙

原版は桃色の横長カードと細い日付だけ。大きい紙の裏面を実日付の面にし、日付と内容の関係を折りで作る。

- 各記録は一枚の平らな読む紙。論理先端に幅84〜104pxの大きい折り耳を起こし、`time`をその無変形の前面に置く。折り耳には上・下の三角の小口と、紙へ戻る幅20pxの実接合を持たせる。
- `summary`と本文は折り耳の反対側の広い自由面へ置く。紙の外側は四辺枠にせず、折り耳の下に20〜28pxの実空隙を開ける。実日時が長ければ耳の高さも自然に増える。
- 先端の折り耳だけが立ち、本文は一面。次の紙とZ字に接続しない。説明を開いた時も日付の位置と接合上端は固定し、読む紙だけ下へ伸びる。
- 狭幅は折り耳を上の全幅日時面へ移し、片側の20pxの戻りだけで下の記録紙へつなぐ。耳の左右両方を囲って普通の箱にしない。

近似注意：R413の全高の折背、R403/R523の連続Z折、R533の人物表紙フラップを繰り返さない。違いを作るのは、各イベントの**実日時が立つ短い折面を占め、本文の自由面と一対になる**配置。小さい角折りを追加するだけなら不可。

## R554 Stone Milestone — 一つの岩の割れ目を時系列の断面として読む

独立した丸角の石カードを増やさず、一つの連続した岩体に記録を刻む方向。

- 全リストを一つの縦長の露頭とし、左に幅72〜96pxの日付の切断面、右に広い記録面を作る。その間に幅24〜32pxの大きい不規則な割れ目を通す。
- 各実日時の位置で割れ目に一つの横の切込みが入り、同じ高さのsummaryへ対応する。割れ目の両輪郭は相補的な端点を持ち、本文の段落に応じて場当たりにギザギザを増やさない。
- 日付側と記録側は、イベント上端の幅28〜36pxの残った石の橋でつながる。橋の上下には真の裂け目を残す。本文は広い平面で、開閉しても上の橋と日時を動かさない。
- 外周は一体の不均等な切断面にし、各イベントの四辺枠や一枚ずつの楕円座を作らない。狭幅では日時を各記録の上の切口へ戻し、側の割れ目が読む幅を奪わないようにする。

近似注意：R394の階段、R494の連続アーチ、R174の別々の割石を転用しない。ここは**同一岩体を分ける実割れ目と、日時に対応する残存橋**が主構造。年代間隔を石の厚さとして偽って表現しない。図形寸法は単に内容の収納量である。

## R555 Ledger Event — 残る日付の控えと、開く記録面

黄色い表と罫線の密度変更だけでは足りない。一冊の見開きではなく、記録を増やしても残る一本の控えを形にする。

- 全高の日時控えを幅92〜112pxで一本通し、各イベントの本文紙との間を24px開ける。控えは実`time`だけを載せ、架空の通し番号や集計値は足さない。
- 各summaryの高さに幅40〜48px・高さ28〜36pxの紙の残し橋を置き、控えと本文紙を各8px以上重ねて一体にする。控えの切離し縁は大きい切込みで読み、細かい偽ミシン目だけで済ませない。
- 右の本文紙は一つの広い横長面。見出しと状態を上辺に固定し、description/meta/linkが下へ展開する。独立した札を積層せず、一本の控えが全時系列を保持する関係を見せる。
- 日付は等幅18〜22px、見出しはセリフ16〜18px、本文14px。3種の実情報だけで帳簿の密度を作る。狭幅は日時を上へ回し、控えと本文の残し橋を横向きに保つ。

近似注意：R084の二枚票、R275の二用途紙、R391の背＋各葉と似せない。個々の小さい日付札ではなく**一覧を貫く控え**と、開閉する記録の関係が必要。紙橋と日付控えが装飾線にしか見えない場合は再考する。

## R557 Console Log — 全記録を載せる開いた金属チャンネル

架空の計器を作らず、日時と実ログを別の読む面として同じ一体材に置く。

- 全リストを一つの開いたL断面のチャンネルへ。幅88〜108pxの後ろの日時面と、幅24pxの露出した折曲げ面、広い前のログ面を一体につなぐ。右端は開き、四辺の外ケースを作らない。
- 後ろの面は実日時だけ、前の面にはsummary/title/statusと開く本文。状態はsummary内の文字と幅4〜6pxの接点の面で示す。時系列を表す細線とノブを別に追加しない。
- 面の折曲げ部分は全高に同じ断面を持つが、各イベント上端だけ幅24pxの実切込みを作り、後ろの日時と前のsummaryの行の対応が分かるようにする。薄い縦罫へ還元しない。
- 上端と下端に露出したL断面を大きく見せ、長文を入れても材が途切れない。狭幅は日時面を各行の上の24px折曲げに続け、本文幅を確保する。

近似注意：R537の表示面＋首＋台、R297の二面console、R282の測定軸＋各候補梁の再利用はしない。ここは**一本の連続した開放チャンネルに二つの実読面を置く**構造であり、イベントごとの面取り箱にはしない。既存L支持は多いため、小さいL線を添えるだけなら不可。

## R558 Stitched History — 時系列をつなぐ大きい連続チェーンステッチ

紫の線を破線へ替えるだけでは不可。日付と記録の接点で糸の前後が変わる縫製を主形にする。

- 全イベントを同じ幅の布へ置き、日時の側に幅48〜64pxの露出した縫い代を予約する。summary/bodyは布の広い平面、日時はsummaryの直上に固定。
- 各イベントに一つの大きい長円のチェーンループを設け、上のループの先端を次のループがくぐる連続経路にする。ループ幅28〜36px、native押面の外へ完全に分離。単なる縦の小穴列や横棒は使わない。
- 一つの実孔で糸が裏へ入り、次のイベントの孔で前へ戻る前後関係を作る。布の全レイヤーに孔を通し、前糸・裏糸を重ね順で分ける。長い本文で距離が増えても糸の両端は実孔に固定し、余分な偽のステッチを本文上へ増やさない。
- 狭幅でも本文を細列にせず、縫い代を24〜32pxへ収めるか上の横縫い代へ回す。同じチェーンのつながりを保つ。状態はnative statusで読み、糸の色だけへ依存しない。

近似注意：R378の二孔を直線で結ぶ週片、R538の二布間の横糸、R431のC綴じを反復しない。**互いをくぐる一続きのチェーンループ**と、実イベントごとの固定孔が差の中心。CSSで真の前後を表現できないなら小さい擬似破線で妥協せず、構造を簡素化して実接点を優先する。

## 実装前に固定したい判定点

1. 同じ3実イベントを全開にした画像で、色を失っても5案の主輪郭と情報配置を区別できるか。
2. 実summaryは一つ、日付は一つ。装飾用の複製文字・偽操作を増やしていないか。
3. 接合の始点と終点を数値で示せるか。長文、1件、全閉、全開、RTLで浮く端がないか。
4. 320pxで本文14pxとsummary44pxを保持し、長い日付を勝手に省略しないか。
5. 案に記した近似との差が実画像に出ているか。説明文だけで違いを主張しないこと。
