# B043 round-3 予備造形確認

正式レビュー前の所見。主担当の実native `sheet-3.png`、R591/R594/R598の個別初期像、immutable sourceの構造・説明を確認した。今回は独立ブラウザでAPI全条件を再実行しておらず、全10件の合否記録ではない。既知の二重outlineとR593入口背景欠落は修正予定として区別する。通常の色・名前だけでAの独立性を認めない。

- **R585**：52px番号／26px名／36px見出しと朱罫は読みやすいが、大数字の手順列＋通常フォームという配置はR579および旧R565に近い。数字を大きくするだけでなく、実現在章と実入力の組版関係を主形へ変える必要がある。例えば現在の大きい章名を一つの縦の欄外見出しとしてフォームの自然高へ組み込み、過去／未来の実章を別の短い通し行として扱う。単に装飾文字を増やさず、現在の意味と入力の読み順が外形を決めるかを実像で判断したい。
- **R591**：丸底の入力欄と、同じ半円切欠き＋6px小口の候補カードが分離している。旧R252半券・旧R385票反復と同じく、一枚ごとの切欠きだけでは主構造が弱い。検索口が本当に候補を保持する一つの深い開口となり、候補の実metaが開口の外に残る索引端、名前／説明は引き出された読む胴となる等、保持側と実内容の関係を作る方向がよい。全候補へ同じ四辺枠を付ける案は避ける。
- **R593**：背景修正後、上の折面と下の候補紙の実接合を確認する。既承認R575の一方向の巻返し、R222三面折りと近いため、ただの上下二面＋右返しでは独自性を説明できない可能性がある。現段階で合格確定しない。
- **R594**：大きい丸角の外板と、同一の右下切角カードの反復。石の支持関係より通常のカード一覧に見える。形状を変えたカードを増やすのでなく、全実候補が一つの連続した岩の切断面へ現れる構成、検索口をその切断の起点へ置く等、単一材料の関係から再検討する。R394階段／R554縦の岩裂け／R374平日と週末の二面をそのまま転用しない。
- **R595**：題字42px・候補見出し30px・朱のmetaは一般的な編集誌面。旧R565や旧R401が持った「大きい字と朱罫のみ」の弱点に戻っている。R585とも組版上の似方が強い。実queryと実candidateの照合という検索固有の関係を、見出し／説明／metaの位置・比率へ反映させたい。架空のスコアや文字を追加して差を作らない。
- **R597**：共通レールと候補腕は一応主形を作るが、R282測定軸／R302通知レール等との近似を正式時に検証する。単なる縦軸から矩形を吊る反復が既承認差分で十分か、実queryと結果の支持階層に意味があるかを確認予定。
- **R598**：実画像で糸の斜線が穴の間を通る。sourceは孔が`before top:-12px`＋周期26pxのy8、糸は別原点の`repeating-linear-gradient(164deg)`であり、縦の位相も斜線の周期も孔中心へ保証されない。個々の短い背は結果間で離れ、一本の縫合でもない。まず実孔中心を共通座標とする連続した縫合経路へ。R378/R538/R157と同じ「孔に糸」だけを再演せず、検索結果の実資料をどう束ねるかという全体の関係も必要。
- **T R592/R596/R599**：元形の保持・実名／説明／metaの可読性改善という方向は妥当。正式時は狭幅・RTL・状態・nativeの検査を行う。
