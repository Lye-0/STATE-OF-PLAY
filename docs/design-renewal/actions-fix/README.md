# Actions 修正記録

対象: `e39f2c5c8e1c3ec3ca739d19dd31f4f92cf96743` の後続修正。
ユーザー提供の Linux / Windows のログと、Verify #93 の失敗ステップを照合した。添付ログ原本はリポジトリ外に保存し、Git には追加しない。

## 原因と変更

- **Continuum**: 新しい EXPANSION-50 ローダーが CONTINUUM タグを共有するため、以前の「インライン用 B 8件」の固定寸法検査に混入した。寸法契約は元の8件に限定し、文字色の継承検査は全13件のBに維持。追加B5件は固定ラベル色をルートへ移し、初期表示を保ちながら指定文字色へ追従させた。追加分もアニメーション・pause・reduced motion・狭幅・破棄の共通検査対象に残す。
- **Liquid Glass gallery**: 透明感を強めた現行仕様に対し、カレンダー、検索欄、通知の検査が以前の濃いアルファ値を要求していた。A は透明感を保ち、B は A より濃くなること、ぼかし・solid 設定・展示と実操作の一致を検査する。色のアルファは文字列表記の正規表現ではなく Canvas で測定し、CSS の新旧表記に対応する。通知は固定時間の待機ではなく実際の色遷移の完了を待ち、CI負荷による途中フレームの比較を避ける。
- **Expansion 30 / React**: 起動後に作成する配布用 React fixture の依存検出が Vite の再最適化を起こし、既存 URL が `504 Outdated Optimize Dep` になる。React の依存一式を事前指定し、fixture ごとにキャッシュを分離する。固定した検査画面では HMR とファイル監視を停止する。展示検査の新規キャッシュでも自動依存走査が大量のソースを読み込み、約7.9GBのプロセスメモリーと初期待機のタイムアウトを起こしたため、事前指定したReact依存を使い、自動走査を停止する。console error の検査は残す。
- **Expansion 50 / radios**: 説明文・番号などの文字色に実際のコントラスト不足があった。15件の文字色を同系の濃色に変更。輪郭、装飾、レイアウト、操作 API は変更しない。20件のラジオについて全選択状態・非選択状態を四つの React 配布形式で検査する。失敗情報は全カテゴリ分を集計してから失敗させ、最初の失敗に後続の問題が隠れないようにした。
- **後続の選択文字検査**: 全730件のReact四形式検査により、ページ送り1件・タグ8件の不足も発見。実背景を独立検査で確認し、選択文字だけ同系濃色へ変更。ページ送りの別4件は文字の背後が疑似要素の不透明面であり、祖先の明るい面との比較は誤検出だった。4件については実際の `::before` の色・不透明度・可視性を確認して同じ4.5基準で測定する。
- **総ページ数・未選択の文字**: 後続の回帰検査で14ページャーの補足文字、および2件の矢印・未選択数字にも不足が判明。実描画の背景で照合し、16個の文字色トークンを調整した。矢印位置、全12状態・4画面幅、連続キー操作、終端でのフォーカス検査は維持する。
- **独立した視覚検査**: Astra medium が実際に描画された装飾面のピクセルを測定し、DOM の祖先背景色だけでは検出できなかった4件の番号の不足を発見。追加で番号色を濃くした。ラジオ15件と後続9件は再検査に合格。詳細は `review/` と色変更JSONを参照。
- **Tab strip**: スキンの `overflow:auto` が「横スクロール不要」の共通規則を上書きする不具合を、状態セレクターの優先度で修正。色は独自変数の有無ではなくテーマの実効色を検査する。狭幅で3タブが収まらない設計でも、実際にスクロールでき、選択タブが見えることを検査する。
- **Signature**: 提供された添付にはこのステップの具体的な失敗本文がなく、元コードの25検査は手元で成功した。React の同じ後発最適化要因を除くため共有 fixture サーバーへ移行し、再検証する。元の失敗と原因が完全に同一だったとは断定しない。
- **開発サーバー**: 大量のレビュー資料のコピーにより監視上限を使い切る問題を避けるため、`docs/` を監視対象から外す。実際の作者ソースの更新検査は監視を有効にして維持する。
- **Expansion review**: 現行の折り返しセグメントに古い「全3件が必ず1行」の前提を適用していた。行内同幅、非重複、文字包含、ネイティブ入力のクリック範囲、全選択状態での位置安定を検査する。検査用 `section` CSS は外側の fixture に限定し、部品内部の `section` に干渉させない。
- **実描画のコントラスト**: Railcar / Hex Bolster の説明、Relay / Circuit のラベル、Inspection Card の削除操作は、紙の疑似要素や勾配上では読みやすいが、祖先の背景色だけでは誤検出された。5件限定で文字を一時的に隠して実画像の背景ピクセルを測定する。独立測定と照合し、正常色・低コントラスト色・スタイル復元の回帰検査も追加。実情報テキストの基準4.5は維持する。
- **全件画像検査の長時間化**: 全カテゴリのCSSを保持した一つの文書で730件を繰り返し撮影すると、後半の検査が大幅に遅くなった。同じ3テーブルの画像記録の先頭から末尾まで、長寿命ページでは約195秒、新しいページでは約26秒だった（単一比較であり、同時負荷差を含む）。展示検査はカテゴリごとにページとコンテキストを閉じて開始し直す。全730件の操作、状態、狭幅、画像、エラー検出は維持し、対象件数・ID重複も確認する。カテゴリ横断のCSS読み込み順検査は既存のlazy-loadingの開発・本番両モードに残す。この横断検査は代表要素の署名を比較するもので、730件すべての長寿命ページでの全操作と同等とは扱わない。キャッシュはプロセスごとにも分離し、並行するローカル検査の相互干渉を避ける。
- **Workflow**: 同じブランチへの連続 push では古い Verify をキャンセルし、最新の14ジョブを実行する。OS 行列、検査項目、失敗判定は維持する。

## 検証記録

最終結果は `validation.json` に記載。型チェック、本番ビルド、Continuum、Glass gallery、Signature、Tab strip、Expansion 30、Expansion review、実Vite watcher、lazy-loading（開発・本番）の各検査が成功した。Expansion 50は展示730件、React四形式、通常JS両構成を完走。展示はローカルのみ重複しない2組に分けて実行し、合計730件のID一致と必須画像2,920枚を照合した。CIでは引き続き全件と後続検査を実行する。詳細ログ・比較画像・ピクセル測定原票・配布 fixture は `captures/` 等の Git 管理外に置く。
ローカルは Linux、Node.js 22.23.3、システム Chromium 151。Playwright 管理 Chromium の取得はネットワークの403でできなかったため、Windows と CI のブラウザー版を実行済みとは扱わない。
修正後の push で始まる Actions は、ユーザーの指定に従い追跡しない。
