# EXPANSION-50 デザイン再設計

対象は `aec3d001` の再検査で再設計・調整推奨となった517件。維持候補とLiquid Glassは対象外。番号R001〜R730は維持する。

## 作業と検査

- メインは GPT-6.1 Sol / high。約10件を実装・検証後、検査担当 GPT-6 Astra / medium に渡す。
- 検査担当は1人。検査中、メインは次の組を最大10件まで進める。
- 各部品は独立した設計意図を持つ。共通化するのは意味・状態管理・配布契約。配色や共通の装飾を作品の違いと数えない。
- 検査では本体・展開・操作後・狭幅・動きを確認し、730件の比較一覧と過去の修正組も参照する。
- 検査は画像だけでなく操作と実装を参照する。検査する版のハッシュを固定する。
- メインは指摘に対する採用・不採用と理由を保存。重大なUI問題・根本的な再設計は対応後に再検査する。
- 検査・対応・必要な再検査・検証が済んだ組だけをコミットしてmainへpushする。次の組の未検査変更を混ぜない。
- 10件ごとにpush、最終組は残り7件。Actionsの結果追跡は行わない。

## 判定の固定基準

UI要件は `../UI-DIRECTION.md`。文字・値・キャレット・操作領域の安定、即時の状態、ネイティブ操作、長文・狭幅・動き軽減、配布形式の一致が前提。

Aは形・材質・構造・操作時の変化による独自性と美しさを要求する。Bは読みやすさ、節度、汎用性を要求する。どちらも同系統の形を配色だけで量産しない。完成度の参考作品の形をコピーしない。

各指摘は番号、重要度、根拠画像/操作、原因、必要な改善を持つ。検査担当の主観的な好みと再現可能なUI不具合を区別する。何度も判定基準を変えない。完成判定は重要な指摘の対応と必要な再検査の結果で決める。

## 記録

- `targets.json`: 全対象、R番号、組、状態、検査とコミット。
- `progress.json`: メインと検査担当の現在位置、完了数、最後のpush。
- `baseline.json`: 元の検査判定と維持候補を含む比較対象。
- `batches/Bxxx/design.md`: 個別設計意図と類似する既存作品との差。
- `batches/Bxxx/review-N.json` / `review-N.md`: 検査担当の判断、根拠、改善案。
- `batches/Bxxx/response-N.md`: メインの対応と理由。
- `batches/Bxxx/status.json`: 検査版、検証、pushの状態。
- `evidence/` / `batches/*/captures/` / `snapshot/` / `exports/`: 画像・検査版・配布検証資料。容量を抑えるためGit管理外。

原本の添付ファイル・開発チャット全文はここへ転記せず、Git管理しない。提出HTMLは画像内蔵の単体ファイルとし、この作業フォルダへ保存する。
