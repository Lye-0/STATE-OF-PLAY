# v2.3.0 → v3.0.0 移行手順

## 最初に守るもの

既存リポジトリを別の場所へバックアップします。`.git/`、環境ファイル、独自のデプロイ設定、未コミットの変更は保護してください。
ZIPはリポジトリ内容の全体版ですが、Gitの履歴や個人設定まで上書きするものではありません。

## 置き換えの範囲

単なる「すべて上書き」だけでは、ZIPに存在しない旧ファイルが残ります。
バックアップ後、次の区分に沿って入れ替えてください。

| 旧版の場所 | 対応 |
| --- | --- |
| `src/` | **フォルダー全体を新版と入れ替える**。旧`.js`、`exports.json`、`demo/`、`registry.generated.js`を残さない |
| `scripts/` | **全体を入れ替える**。旧独自サーバー／サイト用bundlerは不要 |
| `tests/`、`docs/` | **全体を入れ替える**。新構成用の検証・説明に更新 |
| `packages/` | 旧展開済み生成物。不要になったことを確認して削除 |
| ルートの`assets/`、`vendor/` | 旧ビルド済みサイトと重複vendor。新版では不要 |
| `css/`、`js/`、`preview.html`（初期版の残り） | 新版では参照しない。独自に追加したものがないことを確認して削除 |
| 旧`RELEASE-MANIFEST.json` | 新版のマニフェストに置き換え |
| ルート`index.html`・設定 | 新版へ置き換え。入口がVite用になります |
| `public/` | 新版を配置。vendorはこちらに1か所だけ |
| `.git/` | **残す**。Gitの履歴 |
| `.env*`・独自設定 | **退避・確認して残す**。公開ディレクトリへ移さない |
| `node_modules/` | `npm install`で更新。整合性に問題がある場合だけ作り直す |
| `package-lock.json` | 既存がある場合は`npm install`で更新。新版に合うものをGit管理 |

この手順を自動実行する削除スクリプトは付けていません。独自ファイルを誤って消さないためです。

## 移行後

```powershell
npm install
npm audit
npx playwright install chromium
npm run verify
npm run dev
```

`npm audit`に警告が出る場合は内容を確認し、`--force`で一括更新せず、対象依存を明示して対応してください。
今回のZIPではPlaywrightを1.63.0に固定し、以前の古い指定へ戻していません。

## 意図的に変わるもの

- 開発サーバーはViteへ。ソースHTMLのダブルクリックは使いません。
- 本番配信は`dist/`へ。ルートをそのままGitHub Pagesに公開する設定は変更が必要です。
- 開発中に全パーツ・全形式の`packages/`を作りません。
- 全体ZIPは元ソース中心です。サイトのビルド結果は`npm run build`で再生成します。
- 全形式のZIPを手元に揃えたい場合だけ`npm run export:parts`を使います。

## 意図的に変えないもの

16パーツの外観、アニメーション、カテゴリ・検索、トグル操作、詳細画面、コピー成功表示、選択ファイルの保存、フォルダーツリー、4形式のコード、AI用プロンプト、パーツZIPの内部階層を維持します。
ギャラリーのReact化は行っていません。React向けパーツは引き続き提供します。

コミットする場合の例: `refactor: ViteとTypeScriptへ移行して配布生成物を整理`
